# 适配新设备型号

本指南面向想把本插件扩展到其他松下设备型号的开发者。所需技能：Python 基础 + 能用命令行。

---

## 第一步：确认你的设备信息

运行 `tools/dump_device_params.py`，输出的每台设备包含：

| 字段 | 含义 |
|------|------|
| `deviceId` | 格式 `MAC_CATEGORY_SUFFIX`，category 决定设备大类 |
| `devSubTypeId` | 决定走哪个 API 端点，如 `DCERV-03`、`MIDERV`、`NEWDCERV-01` |
| `deviceMNO` | 设备型号，如 `FY-35ZJD2C` |
| `statusAll` | 上次 GET 缓存的完整状态字段 |

记下你的 `devSubTypeId`，这是后续所有操作的基准。

---

## 捷径：先查官方 Web 控制页（强烈推荐）

松下为部分机型提供了网页版控制页，地址规律是：

```
https://app.psmartcloud.com/ca/cn/<category>/<机型代号>/index.html
```

`<category>` 就是 `deviceId` 中间那段（新风 `0800`/`0850`，浴霸 `0820`，空调 `0900`），`<机型代号>` 通常是 `devSubTypeId` 去掉后缀。例如：

| 机型 | Web 控制页 |
|------|-----------|
| LD5C（FY-25ZDP1C） | `ca/cn/0800/LD5C/index.html` |
| 浴霸 FV-RB20VL1 | `ca/cn/0820/RB20VL1/index.html` |
| 大型空调 | `ca/cn/0900/AirconET/index.html` |

**页面返回 200 就说明这条路走得通。** 该页面没有证书固定，直接下载它的 `js/common/api_utility.js` 就能读到官方协议本身：端点名、完整 payload 字段表、哨兵值、身份字段位置、认证头。这比反编译 APK 或试图抓包快得多，也更可靠——拿到它就可以跳过第二到第四步。

```bash
curl -s https://app.psmartcloud.com/ca/cn/0800/LD5C/js/common/api_utility.js | grep -o 'ADev[A-Za-z]*'
```

### Info 端点家族

从 Web 页读出的协议里有一类端点名中间带 `Info`，与常规命名规律不同，光靠"Get 换成 Set"猜不出来：

- `ADevGetStatusInfoLD5C` / `ADevSetStatusInfoLD5C`（LD5C）
- `ADevGetStatusInfoFV54BA1C` / `ADevSetStatusInfoFV54BA1C`（浴霸 FV-RB20VL1）
- `ACDevGetStatusInfoAW` / `ACDevSetStatusInfoAW`（大型空调）

这类端点的请求形状也和其他端点不同：

- `usrId` / `deviceId` / `token` 放在**请求体顶层**，不在 `params` 里；
- 除 `Cookie` 外还要发 `xtoken: SSID=...` 头；
- payload 用**长驼峰字段名**（`runningStatus` / `runningMode` / `airVolume`），不是 `runSta` / `runM` / `airVo`；
- 每次只改一个目标字段，其余填 255（定时器时/分填 127）。

**如果探测显示某端点 404，先确认是不是漏了 `Info`。** LD5C 的 `ADevSetStatusLD5C` 曾被 404 误判为"端点不存在"，真身是 `ADevSetStatusInfoLD5C`。

> 这条规律由 [dkong5ssss](https://github.com/dkong5ssss/panasonic_smart_china_erv) 定位，并在 FY-25ZDP1C 上实机验证（本仓库 [issue #11](https://github.com/rudyll/panasonic_smart_china_r/issues/11)）。

## 第二步：找到正确的 GET 端点

运行 `tools/probe_endpoints.py` 自动探测所有已知端点的响应：

```bash
python3 tools/probe_endpoints.py
```

脚本会对账号下每台设备依次测试以下端点，并打印结果：

| 端点 | 已知适用设备 |
|------|------------|
| `ADevGetStatusDCERV` | DCERV-03（本项目已实测） |
| `ADevGetStatusNewDCERV` | NEWDCERV-* 系列 |
| `ADevGetStatusMidERV` | MidERV 系列 |
| `ADevGetStatusSmallERV` | SmallERV / 小型新风 |
| `ADevGetStatusLD6C` | LD6C（FV-25ZDP2C 等） |
| `ADevGetStatusNeedsAP` | NeedsAP 系列 |
| `ADevGetStatusJDNeedsAP` | JD NeedsAP 系列 |
| `ADevGetStatusInfoERV` | InfoERV 系列 |
| `ADevGetStatusInfoFloorPlacedERV` | 落地式 ERV |
| `ACDevGetStatusInfoAW` | AW 系列（空调新风一体机） |

**成功标志**：某一行打印 ✅，响应里有 `results` 字典且包含 `runSta` 等控制字段。

**如果全部 ❌**：你的设备对应端点尚未收录。可用以下方法推断：
1. 记下第一步的 `devSubTypeId`（如 `FOOBAZ-01`），按命名规律猜端点：`ADevGetStatusFoobaz`
2. 在旧版 App APK（见第三步）里搜索：`grep -r "devSubTypeId" app_src/sources/ -l`，找到对应类后再搜 `URL_ADEV_GET_STATUS`
3. 找到新端点后，手动加到 `tools/probe_endpoints.py` 的 `GET_ENDPOINTS` 列表末尾再重跑

## 第三步：获取 SET payload 字段表

有了可用的 GET 端点后，GET 返回的 `results` 就是该设备的完整状态。区分两类字段：

**只读传感器**（不能写入 SET）：通常是物理传感器读数，名称规律如：
- `*PMC`（PM2.5）、`*TeC`（温度）、`*HumC`（湿度）、`*CO2*`（CO2）
- `*TL`（滤网剩余寿命）、`offline`、`serverTime`、`hVer`、`sVer`

**可写控制字段**：`runSta`、`runM`、`airVo`、`holM`、`preM` 等，以及对应设备子类的特有字段。

如果能拿到无 Payegis 保护的旧版 App APK（通常是 3.x 版本），可用 jadx 反编译直接查看源码中的 Java bean：

```bash
jadx -d app_src/ your_old_app.apk
# 搜索你的 devSubTypeId 对应的 bean 类
grep -r "devSubTypeId" app_src/sources/ -l
grep -r "generateSetStatusJson\|createADevSetStatus" app_src/sources/ -l
```

关键类通常是 `*DevStatusSetBean.java` 和对应的 `*ParamSettingUtil.java`，里面列出了所有可写字段及默认值（通常为 255 = "不改"）。

---

## 第四步：验证 SET 端点

**SET 端点命名规律**：GET 端点把 `Get` 换成 `Set` 即可，例如：
- `ADevGetStatusNewDCERV` → `ADevSetStatusNewDCERV`
- `ADevGetStatusMidERV` → `ADevSetStatusMidERV`

使用通用工具 `tools/probe_set_endpoints.py`，无需修改 Python 源码。先复制一个已有 profile：

```bash
cp tools/set_probe_profiles/ld5c.json my_device.json
```

profile 的核心结构如下：

```json
{
  "name": "示例设备",
  "deviceFilter": {
    "devSubTypePrefix": "FOOBAR",
    "category": "0800"
  },
  "getEndpoint": "ADevGetStatusFoobar",
  "reportPrefix": "foobar_set_report",
  "schemas": {
    "foobar": {
      "skipFields": {
        "runSta": 255,
        "runM": 255
      },
      "fieldSeries": [
        {
          "prefixes": ["tH", "tMin"],
          "start": 1,
          "end": 6,
          "value": 127
        }
      ],
      "controlFields": {
        "power": "runSta",
        "mode": "runM"
      },
      "allowedValues": {
        "power": [0, 1],
        "mode": [0, 1, 2]
      }
    }
  },
  "probeMatrix": [
    {
      "endpoint": "ADevSetStatusFoobar",
      "schema": "foobar"
    }
  ]
}
```

配置说明：

1. `deviceFilter` 只选择指定 `devSubTypeId` 前缀和 category，避免误控其他设备。
2. `skipFields` 列出普通字段及其“不修改”值；`fieldSeries` 生成 `tH1`–`tH6` 这类重复字段。
3. `controlFields` 把 `power/mode/volume` 等逻辑名称映射到真实 payload 字段。
4. 每个控制字段都必须在 `allowedValues` 明确列出合法整数；工具拒绝发送未列出的值。
5. `probeMatrix` 明确允许测试的 endpoint/schema 组合。端点只能是名称，不能填任意 URL。

先做纯本地校验，不需要账号，也不会访问云端：

```bash
python3 tools/probe_set_endpoints.py --profile my_device.json validate
```

然后提供凭据并按只读 → skip/no-op 的顺序执行：

```bash
python3 -m pip install requests
export PMS_USER='松下智家账号'
read -s PMS_PASS
export PMS_PASS

python3 tools/probe_set_endpoints.py --profile my_device.json inspect
python3 tools/probe_set_endpoints.py --profile my_device.json probe
```

**payload 构造原则**：
1. 所有可写字段全部包含，未要修改的用 255（skip 值）填充
2. 定时器字段的小时/分钟用 127 填充（`tH1-6`、`tMin1-6`）
3. 字段名区分大小写，从 App 源码或 GET 响应直接复制

`probe` 是否无动作取决于 profile 里的 skip 值是否正确。未知字段不要猜；先通过 App 反编译或已验证报告确认。若 SET 返回 `{"results": {"todoId": N}}`，仍需通过一次明确授权的真实控制和控制前后状态确认设备执行。真实控制示例：

```bash
python3 tools/probe_set_endpoints.py --profile my_device.json control \
  --endpoint ADevSetStatusFoobar \
  --schema foobar \
  --field power \
  --value 0 \
  --confirm-model 完整设备型号
```

`control` 要求 endpoint/schema 组合存在于 `probeMatrix`、值存在于 `allowedValues`，且 `--confirm-model` 与设备列表完全一致。

## 排查：todoId 返回但设备不执行

这是最常见的问题，检查顺序：

1. **payload 字段不完整**：对照 App 源码的 bean 类，检查是否有遗漏的必须字段。本项目 DCERV-03 就是因为缺少 `preSet`、`pmSen`、`coSen`、`tvSen`、`userSupWind`、`userExhWind`、`aircJoi` 和定时器 `tM/tWind` 字段而不执行。

2. **端点选错**：`devSubTypeId` 是 `DCERV-03` 就用 DCERV 端点，是 `NEWDCERV-*` 就用 NewDCERV 端点，不能混用。

3. **字段值范围不对**：某些字段的合法值范围比较窄，发超出范围的值服务器可能接受但设备忽略。从 GET 响应的实际值推断范围。

## LD5C（FY-25ZDP1C）：已解决

本机型的控制协议已经确认并在实机上验证通过，普通用户直接升级插件即可，不需要再跑探测工具。

**结论**：LD5C 走的是官方 Web 控制页（`ca/cn/0800/LD5C/`）使用的 Info 家族端点。

| 用途 | 端点 | 说明 |
|------|------|------|
| 读控制状态 | `ADevGetStatusInfoLD5C` | 实时；`runningStatus` / `runningMode` / `airVolume` |
| 读传感器 | `ADevGetStatusMidERV` | Info 端点的传感器字段在本机型全是占位值，只能从这里取 |
| 控制 | `ADevSetStatusInfoLD5C` | 长驼峰字段名，255 = 保持，定时器时/分 127 = 保持 |

请求形状：`usrId` / `deviceId` / `token` 放请求体顶层，认证头除 `Cookie` 外还要发 `xtoken: SSID=...`，每次只改一个目标字段。

已知值域：

| 字段 | 含义 | FY-25ZDP1C 已知值 |
|------|------|-------------------|
| `runningStatus` | 开关机 | `0` 关，`1` 开 |
| `runningMode` | 运行模式 | `0` 热交换，`2` 内循环，`5` 外循环 |
| `airVolume` | 风量 | `1` 低，`2` 中，`3` 高 |

**绕过的弯路**（供其他机型参考）：`ADevSetStatusLD5C`（少了 `Info`）返回 404 曾被误判为"端点不存在"；`ADevSetStatusLD6C` 和 `ADevSetStatusDCERV` 会返回 `todoId` 但设备不动作——**云端返回 `todoId` 只表示请求入队，不代表设备执行**。松下 App 有证书固定，抓包这条路本项目已放弃；改查官方 Web 控制页的 JS 源码更快也更可靠，见上文"捷径"一节。

协议由 [dkong5ssss](https://github.com/dkong5ssss/panasonic_smart_china_erv) 定位，[accpowered](https://github.com/accpowered) 和 `dkong5ssss` 仓库的用户提供实机验证，讨论过程见 [issue #11](https://github.com/rudyll/panasonic_smart_china_r/issues/11)。

**其他机型**若仍需收敛 SET 协议，用通用工具 `tools/probe_set_endpoints.py` 配合自己的 profile（参考 `tools/set_probe_profiles/ld5c.json`）。三种模式都会生成脱敏报告，已隐藏账号、SSID、token、familyId 和完整 deviceId；但不要上传 `dump_*.json` 原始 dump 或自行复制的未脱敏响应。

## SmallERV02（FY-25ZM1C）：已加入专用适配

issue #5 的实机报告确认 `devSubTypeId=SMALLERV02` 使用 `ADevGetStatusSmallERV` / `ADevSetStatusSmallERV`，且风量值为 `1=低、3=高`（与通用 SmallERV 的 `0/1` 值域不同）。集成从 v2.2.3 起对该子型号使用实时状态端点，并只创建报告中实际返回的室外 PM2.5、室外温度和室外湿度传感器；该型号没有 `runM`，因此不创建运行模式控件。v2.2.4 起还会读取 `filClTL`、`oaFilClFirTL`、`oaFilExPMTL`、`reFilExTL` 四个滤网倒计时字段，单位为小时。升级后请在自己的设备上验证开关、风量、假日模式和滤网倒计时，再在 [issue #5](https://github.com/rudyll/panasonic_smart_china_r/issues/5) 回复结果。

## 第五步：实现 HA 实体

确认 GET/SET 工作后，参考现有代码接入 HA：

| 需求 | 参考文件 |
|------|---------|
| 读取传感器 | `sensor.py` |
| 开关控制 | `switch.py` + `select.py` 的 `_build_dcerv_payload()` |
| 模式/风量选择器 | `select.py` 的 `_FreshAirSelect` 基类 |
| 空调温控 | `climate.py` |

新设备子类型最小工作量：
1. 在 `sensor.py` 里增加你的字段映射
2. 在 `switch.py` 或 `select.py` 里增加一个新的 `_build_*_payload()` 函数
3. 在 `coordinator.py` 里按 `devSubTypeId` 分支选择 GET 端点
